# Pilot plan

**Release:** v29
**Date:** 7 November 2026
**Status:** designed, not run.
**Goal:** test whether 3–5 learners can use the module, reach the week-1–2 outcomes, and calibrate confidence.

## Slice

A four-week pilot is enough to test the loop without asking for 55 weeks:

- Week 1: cell as reactor.
- Week 2: water, pH and weak-acid toxicity.
- One brief: Brief 1 (enzyme dossier) or the week-1 repository scaffold.
- One exit ticket per week, scored 0–3.
- One 20-minute usability interview.

## Participants

3–5 learners with a chemical engineering or biotechnology background. No personal health data. Use a participant code, not a name.

## Measures

| Measure | Target |
|---|---|
| Completion of two weeks | ≥80% |
| Exit-ticket score | ≥2/3 median |
| Calibration gap (confidence − score) | ≤1.0 |
| Broken-link or navigation failure | 0 |
| System Usability Scale | ≥75 |
| Claim-source check: find the source for one case-study number | ≥80% |

## Stop rules

- Any participant cannot find the tracker or lecture index → fix navigation before continuing.
- Any exit ticket scored 0 by two participants → rewrite the outcome or the explanation.
- Any claim-source check fails → fix the citation before more content.
- Distress or overload → stop, debrief, do not collect more data.

## Analysis

Use `PILOT-FORM.csv`. Compute median exit score, mean confidence, calibration gap, completion and SUS. Report n, not percentages alone. Do not generalize from five people.

## What the pilot cannot prove

It cannot validate the full 55-week sequence, the exam thresholds, or long-term retention. It can only catch navigation, comprehension and calibration failures early.
